# Troubleshooting

Use when an Android build, unit test, connected test, or generated-model step fails.
## Common Pitfalls

### NDK or Toolchain Missing

If builds fail with NDK-related errors:
```bash
just install-ndk
just install-toolchains
```
The project requires specific NDK and Rust toolchain versions for JNI compilation.

### Gradle Daemon Memory

Long sessions can exhaust the Gradle daemon heap. If builds become slow or OOM:
```bash
./gradlew --stop
./gradlew clean
```

### Generated Model Drift

Never edit files generated by TypeShare or UniFFI. If Android models look wrong after a Core change:
```bash
cd .. && just generate
```
Then rebuild and re-run tests.

Generated Android artifacts typically live in:
- `gemcore/src/main/kotlin/com/wallet/core/primitives/generated/` for TypeShare-generated primitives
- Kotlin files with a `// Generated by typeshare` header
- `../core/gemstone/android/gemstone/src/main/java/uniffi/` for UniFFI-generated bindings used by the `:gemstone` module; these are generated locally by the module's `bindgenKotlin` Gradle task and are not committed, so a changed `#[uniffi::export]` in `core/gemstone` does not compile in the app until the `:gemstone` module rebuilds

If you need Android-specific behavior on top of generated types, add adapters, mappers, or extension functions in regular source files. Do not patch generated output to make builds or tests pass.

### Room Migration Tests

Database migration tests require an emulator or device. Run them separately:
```bash
cd ..
just start-emulator
cd android
just test-integration
```
Do not skip migration tests when changing Room schemas — they catch data loss bugs that unit tests cannot.

### Unit Tests Fail Loading Gemstone

Host unit tests load the Rust `gemstone` library through JNA from `core/target/debug` (configured in the root `build.gradle.kts`). Running `./gradlew :<module>:testDebugUnitTest` for a module that reaches gemstone before that library exists fails with JNA link or class errors unrelated to your change. Build it first, or use `just test`, which does so:
```bash
cd ../core && cargo build --package gemstone
```
If a test still fails on a clean tree with the library present, treat it as environmental: report it with the command and judge only the classes you touched.

### Connected Tests Crash Before Any Test Runs

If `connectedAndroidTest` dies in `App.onCreate` with `SharedPreferences in credential encrypted storage are not available until after user (id 0) is unlocked`, the emulator's user has a lock credential and is still `RUNNING_LOCKED`. Use an AVD without a lock-screen credential, boot it, and wait for `adb shell dumpsys user` to report `RUNNING_UNLOCKED` before installing. Dismissing the keyguard does not help.

## Common Recovery Commands

### Build Failures

```bash
./gradlew clean
just bootstrap
./gradlew build
```

### Submodule Issues

If `gemcore/` or `core/` references are stale after a branch switch:
```bash
cd .. && just setup-git
```
Then rebuild: `./gradlew clean && just bootstrap`.
